# Security policy

## Design summary

- **No secrets.** The plugin has no API keys, tokens, or credentials of any
  kind. Browsing, searching, adapting and favoriting need none.
- **Zero runtime egress.** All 1077 entries and thumbnails ship inside the
  package (`data/`). The plugin makes no network requests at runtime — no
  fetch, no telemetry, no update checks. Prompts are assembled locally and
  handed to whatever image tool you choose to run them in.
- **Local user store.** Favorites and settings live in `~/.dsh/prompt-wall/`
  as plain JSON on your machine and are never committed or transmitted.
- **Read-only data path.** The bundled gallery is served through the plugin
  host's authenticated routes; the client never writes to the package
  directory.
- **Prompt text is data, not code.** Adaptation is pure string
  transformation over bundled entries; nothing fetched or generated by the
  plugin is executed.

## Reporting a vulnerability

Open a **private security advisory** on the GitHub repository
(`aiohow/dsh-prompt-wall` → Security → Report a vulnerability). Please do
not open a public issue for unfixed vulnerabilities. We aim to respond
within 7 days.

## Out of scope

- Vulnerabilities in DSH itself — report those to the DSH maintainers.
- The content of upstream prompts and example images (they are community
  data under their own licenses; for licensing concerns, open a normal
  issue with the template code instead).
- Attacks that already require code execution on your machine.
